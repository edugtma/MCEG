    Lista de componentes

    Para comenzar a trabajar en el proyecto partimos de la siguiente lista de componentes:

    • Un microcontrolador ESP32
    • Dos motores DC con caja reductora
    • Un puente H TB6612FNG
    • Cables calibre 22
    • Una protoboard mediana
    • Un interruptor chico
    • Power bank con cargador tipo c
    • Rueda loca
    • Filamento PLA

    Primer paso: soldar los pines del puente H y probarlo

    Primero soldamos los pines del puente H, porque el módulo TB6612FNG viene sin pines y no se puede conectar a la protoboard hasta ponerlos.

    Cómo lo hicimos: 1. Colocamos los pines en el módulo y los sujetamos para que no se movieran al soldar.

    1. Soldamos con cautín y estaño delgado, cuidando no unir dos pines con estaño de más.

    2. Revisamos que cada soldadura quedara firme.

    Prueba del puente H

    Después de soldar, probamos el puente H con un código sencillo para confirmar que funcionaba. El código hace girar el motor adelante, lo detiene, lo pone en reversa y lo detiene otra vez, repitiendo el ciclo.

    Código de prueba:

    c++

    include

    // Definición de pines

    define AIN1 26 // Dirección 1

    define AIN2 27 // Dirección 2

    define PWMA 25 // PWM (velocidad)

    define STBY 33 // Habilitación del driver

    define PWM_FREQ 1000

    define PWM_RESOLUTION 8

    void setup() { // Configurar pines de control como salida pinMode(AIN1, OUTPUT); pinMode(AIN2, OUTPUT); pinMode(STBY, OUTPUT); ledcAttach(PWMA, PWM_FREQ, PWM_RESOLUTION);

    // Activar el driver (sacar del modo standby) digitalWrite(STBY, HIGH); }

    void loop() { // Giro hacia adelante digitalWrite(AIN1, HIGH); digitalWrite(AIN2, LOW); ledcWrite(PWMA, 200);
    delay(3000);

    // Detener ledcWrite(PWMA, 0); delay(2000);

    // Giro en reversa digitalWrite(AIN1, LOW); digitalWrite(AIN2, HIGH); ledcWrite(PWMA, 200); delay(3000);

    // Detener ledcWrite(PWMA, 0); delay(2000); }

    Pines utilizados

    • AIN1 (GPIO 26): dirección 1
    • AIN2 (GPIO 27): dirección 2
    • PWMA (GPIO 25): velocidad (señal PWM)
    • STBY (GPIO 33): encendido del driver (HIGH = activo)

    setup()

    • Declara AIN1, AIN2 y STBY como salidas.
    • Configura y conecta el canal PWM al pin 25.
    • Pone STBY en HIGH para activar el driver. Si STBY está en LOW, el motor no gira aunque se le mande PWM.

    loop()

    Adelante: AIN1=HIGH, AIN2=LOW, PWM=200, espera 3000 ms.

    Stop: PWM=0, espera 2000 ms. El motor se detiene por inercia.

    Reversa: AIN1=LOW, AIN2=HIGH, PWM=200, espera 3000 ms. Se invierten las direcciones y el puente H gira al revés.

    Stop final: PWM=0, espera 2000 ms y vuelve a empezar.

    Observaciones

    • La velocidad 200 se puede cambiar por cualquier valor entre 0 y 255.
    • delay() bloquea el programa; para hacer varias cosas a la vez hay que usar millis().
    • Con PWM=0 el motor se detiene por inercia, no se frena activamente.

    ¿Qué hace el programa?

    El ESP32 se conecta por Bluetooth con el celular y recibe comandos para controlar el motor. Los comandos se guardan en un buffer hasta que llega un salto de línea; entonces se procesan completos. Así se evitan errores por los saltos de línea que manda la app.

    Comandos

    • F -> adelante
    • B -> atrás
    • S -> detener
    • (+) -> subir velocidad
    • (-) -> bajar velocidad
    • 1 a 9 -> velocidad directa
    • 0 -> detener

    Partes importantes

    bash String buffer = ""

    Es donde se guardan las letras que llegan. bash if (c == '\n' || c == '\r')

    Detecta el fin del comando y lo procesa. bash cmd.trim() y cmd.toUpperCase()

    Limpian el texto y lo pasan a mayúsculas. bash cmd.charAt(0)

    Toma solo la primera letra del comando. bash map(nivel, 1, 9, VEL_MIN, VEL_MAX)

    Convierte un número del 1 al 9 en velocidad real entre 80 y 255.

    Migración a BT Car Controller

    Después de probar varias apps de uso libre para maniobrar los motores, se dejó el Serial Bluetooth Terminal (que vimos en clase) y me pasamos a BT Car Controller, que ya trae una interfaz de carrito prediseñada. Solo ajustamos el código anterior a los comandos que mandan los botones de esa app.

    Además del segundo motor, se añadió giros y velocidades preestablecidas.

    Pines del driver TB6612FNG

    Motor A: AIN1=26 AIN2=27 PWMA=25

    Motor B: BIN1=14 BIN2=4 PWMB=13

    Driver: STBY=33

    Comandos que acepta

    Velocidades preestablecidas: v → baja (120) u → media-baja (160) U → media-alta (200) V → alta (230)

    Mayúscula o minúscula da igual para F, B, L, R, S, pero v, u, U y V sí distinguen mayúscula de minúscula, porque son cuatro niveles distintos.

    Cómo funcionan los giros

    Un giro se logra girando los motores en sentidos opuestos: un motor va hacia adelante y el otro hacia atrás.

    Giro izquierda: Motor A atrás, Motor B adelante. Giro derecha: Motor A adelante, Motor B atrás.

    Así el robot gira sobre su propio eje, sin avanzar.

    Partes importantes del código

    bash String buffer

    Guarda las letras que llegan por Bluetooth hasta que aparece un salto de línea, entonces procesa el comando.

    bash toupper(c)

    Convierte el primer carácter a mayúscula para que F/f, B/b, L/l, R/r y S/s hagan lo mismo.

    bash c == 'v', 'u', 'U', 'V'

    Se revisan antes del switch porque son sensibles a mayúscula y minúscula (cuatro velocidades distintas).

    bash switch (cUpper)

    Decide la acción: F, B, L, R, S, +, - o número.

    bash map(nivel, 1, 9, VEL_MIN, VEL_MAX)

    Convierte un número del 1 al 9 en velocidad real (entre 80 y 255). bash ledcWrite(PWMA, velocidad) y ledcWrite(PWMB, velocidad)

    Mandan la misma velocidad a los dos motores.

    bash actualizarVelocidad()

    Si los motores ya están girando, aplica la nueva velocidad en vivo, sin volver a mandar F o B.

    Diseño y fabricación de la carcasa

    El desarrollo y fabricación de la carcasa para proteger el circuito y la estructura del carrito fue un proceso de prueba y error, pasando por múltiples intentos y cambios de estrategia hasta alcanzar el resultado deseado.

    Cómo lo hicimos:

    Intentamos primero realizar la fabricación mediante corte láser, pero fallamos tres veces consecutivas en los cálculos de medidas y diseño, por lo que decidimos cambiar de enfoque hacia la impresión 3D.

    El modelo inicial diseñado para impresión 3D también falló imprimimos una casa de Snoopy que no logro cumplir con el criterio esperado, pero este aprendizaje nos sirvió para dominar correctamente la parametrización y el modelado 3D.

    Tras ajustar los parámetros, logramos un diseño final cuyas medidas resultaron exactas, permitiendo que la carcasa embonara y entrara a presión de forma perfecta sobre el chasis y la protoboard.

    Finalmente, realizamos la decoración del carrito en equipo para darle el acabado visual definitivo y listo para operar.
